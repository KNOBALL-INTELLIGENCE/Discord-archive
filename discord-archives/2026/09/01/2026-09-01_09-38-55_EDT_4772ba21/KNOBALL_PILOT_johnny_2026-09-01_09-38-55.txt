> John Handoff — Discord Search Feasibility
> 
> Goal
> 
> Figure out whether we can give SARA a simple read-only search function for the KnoBall Discord.
> 
> Example:
> 
> “Find the Cleveland–Denver game Mike used.”
> 
> SARA should search Discord and return:
> 
> * channel
> * author
> * date
> * message excerpt
> * filename/attachment
> * direct link to the original Discord message
> 
> Proposed MVP
> 
> SARA
> ↓
> searchDiscord(query)
> ↓
> KnoBall backend
> ↓
> Discord historical message search
> ↓
> Top matching messages/files
> ↓
> Clickable Discord results
> 
> Discord currently has a guild message search endpoint:
> 
> GET /guilds/{guild.id}/messages/search
> 
> It appears capable of searching historical messages using things like:
> 
> * message content
> * author/channel
> * files
> * videos
> * links
> * attachment filenames/extensions
> 
> Likely requirements:
> 
> * Discord application/bot installed in KnoBall server
> * View Channel
> * Read Message History
> * Message Content access where required
> * secure bot token
> * KnoBall guild/server ID
> 
> What I Want You to Determine
> 
> 1. Will Discord’s current API actually support this reliably for our server?
> 2. Can a bot search old messages/files in channels it can access?
> 3. Can it return attachments and enough IDs to generate a direct jump-to-message link?
> 4. Are there Message Content intent or bot-verification restrictions that affect us?
> 5. Can we implement this cleanly as something like:
> 
> searchDiscord(query)
> 
> 6. Is there any reason we would need our own database/index instead of using Discord search directly?
> 
> First Test
> 
> Before building anything around SARA:
> 
> Create/test Discord access and try to search the KnoBall server for:
> 
> Cleveland
> Denver
> CLE
> DEN
> 
> including messages containing files/videos.
> 
> If we can locate the Cleveland–Denver game from outside Discord and return a direct link to the original post, the core concept is proven.

> 
> Context: We tested Vizard as a way to take full 45–60 minute YouTube/game videos and automatically find touchdowns, turnovers, big plays, and other highlights before sending the best clips into CapCut.
> 
> What Vizard does
> 
> * Standard AI processing is roughly 1 credit per 1 minute of source video.
> * A 54-minute game uses about 54 credits.
> * Credits are charged for processing the source, not per individual short produced.
> * One full game can therefore produce multiple candidate clips from one credit charge.
> * Paid plans provide monthly credit pools, with larger tiers getting more processing capacity.
> 
> Why this matters for KnoBall
> 
> Vizard is a clean example of the pricing structure we have already discussed for KnoBall:
> 
> Subscription tier + included usage credits + optional additional credits
> 
> Instead of making every AI feature unlimited inside a flat subscription, KnoBall could eventually separate:
> 
> Tier = access and permissions
> Credits = expensive AI / compute usage
> 
> Potential credit-consuming KnoBall actions could include:
> 
> * full-game AI analysis
> * video/highlight processing
> * automated scouting reports
> * advanced simulations
> * AI-generated league/media content
> * large data/report jobs
> * premium intelligence operations
